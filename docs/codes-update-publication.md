# 带日期的 Codes 更新文章

2026-10-14 用户要求：每次 Codes 实质更新单独一篇文章，标题和页面显示日期。此规则替代此前只维护唯一 Codes 页的发布形式；来源和事实门禁不变。

## 总入口与独立文章

- `/resources/codes/` 保留为当前汇总入口，承接 `morioh high codes`，继续提供当前 reported 清单、复制和兑换说明。
- 每次新增码、取得明确失效证据、开发者确认或实际兑换验证发生重要变化时，新增 `src/content/wiki/en/resources/codes-update-YYYY-MM-DD.mdx`。
- URL 为 `/resources/codes-update-YYYY-MM-DD/`。同一天第二次不同变化另用 `-2`，之后依次编号；不覆盖已发布文章，不修改原 URL。相同事件重试不能再生成一篇。
- 英文标题示例格式为 `Morioh High Codes Update — October 15, 2026`；这个日期仅示范格式，不表示已存在该更新。不同同日文章应在标题注明实际变化或 Update 2，保持标题唯一且不超过80字符。
- frontmatter `date` 使用 Asia/Shanghai 的实际发布日期；正文首屏可见英文日期、这次的最小有效答案和验证状态。原始消息发布日期、采集日期和 `sourcesChecked` 单独保存，不能冒充兑换成功日。

## 每篇真正回答什么

1. 哪些码是本次新增、确认失效或验证状态改变，与上一次状态有什么差异。
2. 每条变化的可核验来源、来源日期和采集日期；开发者确认、媒体报道、本站实际兑换分别标识。
3. 仅对本次涉及的码提供原生复制按钮；奖励省略。只从读过的同游戏来源取得字符串，不能补猜测码。
4. 用可见说明指出它是当日历史记录，当前总清单在 `/resources/codes/`；至少三个有用内链，优先总入口、Controls、How to Get a Stand，需要时链接上次更新。

直接复用模板文章与来源面板：category resources、英文正文从H2开始、独立description（40–165字符）、summary、sourcesChecked/sourceNote/citations、已有原创封面及准确ALT。只复用可证明的素材和操作说明，不把整份总清单与兑换攻略复制成日期页。使用现有 Roblox/codes 标签，draft和noindex遵循真实质量状态。

## 同步与去重

同一批合格变化一起更新候选表、总入口及其倒序更新链接、独立文章、证据记录和 `research/codes-update-history.json`。历史表记录稳定事件标识、涉及码及前后状态、来源、文章路径、发布日和实际部署验收状态。重试复用既有事件和文章；仅检查时间、来源排版/奖励差异、请求失败不构成新事件。

发布前仍跑内容、构建、内链、SEO和广告门禁，并核验新URL、总入口链接、Sitemap、正式marker和搜索。回执成功前保持本地或待部署状态，不假称上线。原生构建会把合格MDX加入列表、RSS和Pagefind；无需新增框架或分类。

`tools/audit-seo-geo.mjs` 是2026-10-14固定样本的历史回归工具，包含固定六文/七码断言，不是新增内容的通用门禁。当前发布使用动态的 `audit-build.mjs`、`audit-ads.mjs`、内容/内链门禁和 `audit-seo-geo-live.mjs`；后一项按本次构建检查可变码数和内容，不按历史七码锁死。

无实质变化不发文、不更新文章日期。不倒填“今日新码”，不为日检自动制造大量日期页。此次只改变后续发布规则，没有声称取得新的码，也未创建第一篇更新文章。
